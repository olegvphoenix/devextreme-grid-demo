О программе

Демонстрация возможностей DevExtreme DataGrid (DevExtreme UI for Angular) по списку требований: серверная пагинация, сортировка и фильтрация, Excel-подобные фильтры с диапазонами, сохранение состояния, режимы выбора и копирование в Excel, шаблоны ячеек, серверная группировка с агрегатами, экспорт всех данных в Excel и PDF. Для каждого требования в разделе «Итоги» сказано, закрывает ли его DevExtreme штатно (конфигурацией), с доработкой (своим кодом) или не закрывает.

Данные — производственные записи детерминированного генератора на мок-сервере (ASP.NET Core, .NET 8); набор 1 000, 100 000 или 1 000 000 строк переключается на основной странице. Запросы грида на сервере выполняет DataSourceLoader из DevExtreme.AspNet.Data по IQueryable в памяти; экспорт строят MiniExcel и PDFsharp (версии — в server/MockServer/MockServer.csproj).

XPO не использован: он требует базу данных и пакет DevExpress.Xpo, а DataSourceLoader работает с любым IQueryable — XPO подключился бы позже через XPQuery<T> без изменения контракта API. В задании XPO «если необходимо» — здесь не необходимо.

Версии

Из package.json, точные версии без диапазонов. Angular 12 ограничивает DevExtreme версией 23.2 (24.1 требует Angular 16).

Ловушки версии 23.2.15 на Angular 12

  • BrowserTransferStateModule обязателен в AppModule: каждый компонент devextreme-angular 23.2 инжектирует TransferState, которого Angular 12 сам не даёт — сборка зелёная, в рантайме NullInjectorError.
  • Лицензия: ключ задаётся config({ licenseKey }) до первого компонента; без ключа — только предупреждение W0019 в консоли, баннера и водяного знака нет, работа не блокируется. Коммерческое использование всё равно требует лицензии. Ключ в репозиторий не коммитится.
  • DxTemplateDirective входит в зону Angular на каждый шаблон: перерисовка грида вне зоны (API грида из runOutsideAngular или консоли) превращает страницу в 500 строк с шаблонами из 1,2 с в 19–22 с.
  • DataSource.cancel не прерывает HTTP-запрос; отмена устаревших запросов — отписка от HttpClient в своём коде, и promise отменённой загрузки надо завершить явно, иначе панель загрузки грида остаётся.

Как пользоваться

  1. Запустите мок-сервер (npm run mock) и приложение (npm start), откройте основную страницу.
  2. Выберите размер набора («Строк»); на 1 000 000 строк первый запрос генерирует набор, около секунды.
  3. Фильтр колонки — иконка воронки в заголовке: список значений с поиском, для чисел и дат ещё поля «с / по» в том же окне. Снятые фильтры — чипы над гридом.
  4. Режим выбора — в списке «Выбор»; копирование — кнопка с иконкой рядом с ним или Ctrl+C, вставляется в Excel таблицей.
  5. Меню «Экспорт»: «Excel (сервер)» и «PDF (сервер)» выгружают все строки под фильтром; «штатно» — exportDataGrid для сравнения, его пределы — в «Итогах».
  6. Все изменения сохраняются в LocalStorage и видны на странице «Сохранённые настройки»; пункт «Сбросить настройки» в меню «Ещё» на основной странице очищает их.

Итоги

По каждому требованию задания: оценка покрытия DevExtreme, строк своего кода, использованные API, ограничения и баги, ссылка на раздел демо. Оценка ставится по факту работы в браузере и замерам (docs/measurements.md), а не по ожиданиям: всё, что потребовало своего кода сверх конфигурации, — «с доработкой».

В задании колонка называется «Использованные API Kendo» — остаток шаблона другого вендора; здесь она называется «Использованные API DevExtreme». Строки кода посчитаны scripts/count-loc.js по выделенным файлам без пустых строк и комментариев; тесты и обвязка страницы грида (grid.component.*, {{ sharedLoc }} строк, обслуживает все требования) не разнесены по требованиям. Строки «дополнение» — сверх задания, в балл не входят.
