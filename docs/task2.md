# Промпт для агента-разработчика: демо-приложение с DevExtreme UI Grid

**Роль:** ты опытный fullstack-разработчик (Angular + .net 8+), знаешь DevExtreme UI for Angular (DevExpress).

**Задача:** собрать демо-приложение, которое показывает возможности грида DevExtreme UI for Angular по нашему списку требований. Приложение должно честно показать для каждого требования, закрывает ли его DevExtreme «из коробки» или нужен свой код. Если что-то не реализуется, это фиксируется, а не скрывается.

## 1. Окружение и ограничения

- **Angular 12** (TypeScript 4.3.x), чтобы совпадать с целевым проектом. Проверь какая максимальная версия DevExtreme совместима с Angular 12, используй её при разработке. Зафиксируй точные версии всех пакетов в `package.json` и README.
- Лицензия: опиши процесс применения лицензии, если требуется.
- Тема: material UI, если доступна. Локализация на русский язык (локаль `ru-RU`, формат даты `dd.MM.yyyy`).
- Бэкенд: мок-сервер на .net 8 с серверной пагинацией, сортировкой и фильтрацией. Используй XPO, если необходимо. Плюс локальный генератор данных.

## 2. Набор данных

Сгенерируй производственные записи. Количество задаётся переключателем: 1 000, 100 000 и 1 000 000 строк.

| Поле | Описание |
| --- | --- |
| `id` | Идентификатор |
| `date` | Дата производства, с 01.02.2020 по сегодня |
| `plant` | Завод |
| `line` | Линия (зависит от завода) |
| `product` | Продукт (зависит от линии) |
| `batch` | Партия |
| `netWeight` | Нетто, кг, дробное |
| `grossWeight` | Брутто, кг, дробное |
| `qty` | Количество, целое |
| `markingCode` | Код маркировки DataMatrix, строка |
| `ean13` | Штрихкод EAN13 |
| `status` | enum: Новый, В работе, Агрегирован, Закрыт |
| `operator` | Оператор |

### 3.1. Основная страниц
Содержит грид-демонстратор.
Покажи на экране время первой отрисовки, время сортировки и фильтрации, FPS при прокрутке (простой счётчик через `performance.now()` и `requestAnimationFrame`).

Требования для демонстрации:
- Пагинация с загрузкой только текущей страницы (серверная, привязка к мок API).
- Колонки должны иметь возможность закрепления, перемещения, изменения ширины.
- Продемонстрировать заполнение всей ширины страницы колонками, а также возможность перейти в режим горизонтального скрола, если колонки не помещаются.
- Должна быть форма для скрытия/отображения колонок
- Сортировка отдельно для каждой колонки
- Фильтрация отдельно для каждой колонки
  - Для всех колонок фильтр по списку значений с множественным выбором (Excel-like).
    - Список значений получается с сервера.
    - Список значений колонки строится с учетом фильтров, наложенных на другие колонки.
  - Для числовых колонок дополнительно фильтр по диапазону (поля с / по), в том же popup, что и список чекбоксов
  - Для колонок дат дополнительно фильтр по диапазону (поля с / по), в том же popup, что и список чекбоксов
  - Для всех колонок (включая enum) в фильтрах показывать отображаемые значения
- Все пользовательские изменения (включая настройки колонок, сортировку, фильтрацию, номер страницы) должна автоматически сохраняться при уходе со страницы и восстаналиваться при повторном заходе (а также при обновлении). Хранение в LocalStorage.
- Выбор строк
   - Переключение между: отключено, строки, мультивыбор строк с чекбоксами, мультивыбор строк без чекбоксов, выбор ячеек
   - Копирование выделения в буфер в формате для вставки в Excel.
- Шаблоны ячеек
  - Бейдж статуса
  - Кнопки действий
  - Ярлыки, с возможностью добавления/удаления
- Индикатор загрузки, обработка ошибки сервера, отмена устаревших запросов.
- Серверная группировка с агрегатами.
- Экспорт (в Excel и PDF) для текущего представления с учётом текущего вида грида (колонки, сортировка, фильтры). Выгрузка всех данных, а не только видимой страницы.

## 4. Требования к коду и сдаче

- Структура: отдельный lazy-модуль на каждый раздел, общий `DataService`, свои фильтры как переиспользуемые компоненты (`DateRangeFilterComponent`, `DependentMultiCheckboxFilterComponent`, `ExcelNumericFilterComponent`).
- Без `any` там, где можно типизировать. Модели данных в `models/`.
- README: установка, активация лицензии, версии пакетов, запуск мок-сервера (`npm run mock`) и приложения (`npm start`), найденные ограничения.
- Юнит-тесты на логику фильтра дат (min/max и автоподстановка) и на зависимый список.
- TESTCASES.md: список тестовых случаев для ручного тестирования
- Не придумывай API. Если свойства нет в документации версии, совместимой с Angular 12, напиши об этом и сделай обходной путь.
- Проект должен компилироваться, запускаться, unit-тесты проходить
