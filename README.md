# devextreme-grid-demo

Демо-приложение, которое показывает возможности грида **DevExtreme DataGrid**
(DevExtreme UI for Angular) по списку требований из `docs/task2.md`. Для каждого
требования приложение честно показывает, закрывает ли его DevExtreme «штатно»
(конфигурацией), «с доработкой» (своим кодом) или «не реализуется»; оценки,
строки своего кода, использованные API и ограничения собраны на странице
«О программе → Итоги», а здесь — в разделе [Найденные ограничения](#найденные-ограничения).

Клиент — Angular 12.2 + TypeScript 4.3 + DevExtreme 23.2 (максимальная версия,
совместимая с Angular 12: 24.1 требует Angular 16). Сервер — мок на ASP.NET Core
(.NET 8) с серверной пагинацией, сортировкой, фильтрацией, группировкой,
агрегатами и экспортом всех данных; данные — детерминированный генератор
производственных записей на 1 000, 100 000 или 1 000 000 строк.

Ручные тестовые случаи — в [TESTCASES.md](TESTCASES.md), замеры — в
[docs/measurements.md](docs/measurements.md), спецификация — в
`docs/superpowers/specs/2026-10-31-devextreme-grid-demo-design.md`.

## Запуск

Две команды в двух терминалах:

```bash
npm run mock     # dotnet run --project server/MockServer → http://localhost:5080
npm start        # ng serve → http://localhost:4200, запросы /api проксируются на :5080 (proxy.conf.json)
```

Откройте <http://localhost:4200/>. Разделы приложения (меню сверху, каждый —
отдельный lazy-модуль):

| Раздел | Адрес | Что там |
| --- | --- | --- |
| Основная страница | `/grid` | грид-демонстратор: переключатели, чипы фильтров, панель метрик, DataGrid |
| Сохранённые настройки | `/settings` | содержимое LocalStorage приложения — ключи с префиксом `dxgrid-demo:` и их значения |
| О программе | `/about` | назначение, версии, ловушки версии 23.2.15 на Angular 12, раздел «Итоги» с таблицей по требованиям и баллом |

Первый запрос к набору данного размера генерирует набор на сервере: 1 000 000
строк — около секунды (734–762 мс в замере), после этого набор живёт в памяти
процесса (1,4–1,6 ГБ для миллиона строк). Перезапуск сервера сбрасывает
наборы и добавленные ярлыки.

Проверка сервера без клиента: `curl http://localhost:5080/api/health` →
`{"status":"ok"}`.

## Тесты

```bash
npm test                              # Karma + Jasmine, один прогон в ChromeHeadlessNoSandbox
dotnet test server/MockServer.Tests   # xUnit, сервер поднимается через WebApplicationFactory
```

Клиентские тесты покрывают логику, которую требует задание: модель диапазона
дат (`date-range.model.spec.ts`: min/max, автоподстановка парного поля,
зажим в границы, очистка автоподставленного значения) и зависимый список
(`dependent-list.model.spec.ts`: сохранение выбора при перезагрузке, усечённый
ответ, устаревший ответ), а также выражение фильтра, числовой диапазон,
состояние грида, выделение ячеек, формат буфера обмена, запрос экспорта,
страницы настроек и «Итогов». Серверные тесты — генератор (детерминизм,
зависимости завод → линия → продукт, EAN13, границы дат), `/api/rows/query`
(пагинация, сортировка, фильтр, группировка, агрегаты), `/api/distinct`,
`/api/stats`, ярлыки, экспорт XLSX (читается обратно) и PDF (число страниц),
заголовки `X-Demo-*`.

Браузерная приёмка — по [TESTCASES.md](TESTCASES.md) на наборах 1 000 и
1 000 000 строк; результаты прогона — в [docs/acceptance.md](docs/acceptance.md).

## Лицензия DevExtreme

DevExtreme — коммерческая библиотека; в этом репозитории ключ лицензии не
хранится, и для запуска демо он не нужен. Факты для установленной версии
23.2.15, проверенные по коду пакета и в браузере:

- Без ключа DevExtreme пишет в консоль предупреждение
  `W0019 - Unable to Locate a Valid License Key`; баннера и водяного знака нет,
  работа компонентов не блокируется. `W0020` — ключ устарел, `W0021` — ключ
  неверный.
- Проверка ключа выполняется один раз на приложение, при создании первого
  компонента. Отдельной утилиты для ключа в 23.2.15 нет —
  ключ задаётся вызовом `config`.
- Коммерческое использование требует лицензии независимо от того, выводится
  предупреждение или нет.

Как применить ключ:

1. Войдите в личный кабинет DevExpress (<https://www.devexpress.com/ClientCenter/>),
   раздел с лицензионными ключами DevExtreme, скопируйте ключ своей подписки.
2. Создайте файл `src/devextreme-license.ts`. Он уже в `.gitignore`: ключ
   в репозиторий не попадёт.

   ```ts
   export const licenseKey = '<ваш ключ>';
   ```

3. В `src/main.ts` до `bootstrapModule` вызовите `config` из `devextreme/core/config`:

   ```ts
   import config from 'devextreme/core/config';
   import { licenseKey } from './devextreme-license';

   config({ licenseKey });
   ```

   `config` должен выполниться до создания первого компонента DevExtreme —
   место в `main.ts` перед загрузкой `AppModule` это гарантирует.

4. Пересоберите приложение; предупреждение W0019 из консоли исчезает.

## Генератор данных

`server/MockServer/Data/DataGenerator.cs` — детерминированный генератор с
фиксированным seed: один и тот же размер всегда даёт одинаковые строки. Набор
строится лениво при первом запросе размера и держится в памяти.

| Поле | Как генерируется |
| --- | --- |
| `id` | 1…N |
| `date` | от 01.02.2020 до сегодняшнего дня; у первой строки всегда 01.02.2020, у последней — сегодня |
| `plant` → `line` → `product` | вложенный справочник `Catalog.cs`: 4 завода (Север, Юг, Восток, Запад), у каждого свои линии (С-1…, Ю-1…, В-1…, З-1…), у каждой линии свои продукты; значения не смешиваются |
| `batch` | `P-<ггММ>-<0000>` |
| `netWeight` | 0,5–50,0 кг с шагом 0,1 |
| `grossWeight` | нетто + 0,1…5,0 кг, шаг 0,1 |
| `qty` | целое 1–5 000 |
| `markingCode` | DataMatrix-строка `010<EAN13>21<серийник>` |
| `ean13` | 13 цифр с верной контрольной суммой, один код на продукт |
| `status` | 0 Новый, 1 В работе, 2 Агрегирован, 3 Закрыт |
| `operator` | 12 операторов |
| `labels` | дополнение к заданию: у ≈15 % строк один-два ярлыка из шести (срочно, брак, проверено, на складе, отгрузка, возврат) |

Тот же генератор доступен отдельной командой:

```bash
npm run generate -- 1000 rows.csv     # dotnet run --project server/MockServer -- generate 1000 rows.csv
```

Пишет CSV с заголовком и N строками; размер — любое положительное целое.

## Страница грида

Панель над гридом:

| Группа | Элемент | Что делает |
| --- | --- | --- |
| Строк | выпадающий список 1 000 / 100 000 / 1 000 000 | размер набора; переключение перечитывает первую страницу с `totalCount` |
| Колонки | переключатель «По ширине» / «С прокруткой» | «По ширине» — колонки делят ширину страницы по процентам (`fitPercent` колонки), горизонтальной прокрутки нет, растягивание колонки сжимает соседнюю (`columnResizingMode: 'nextColumn'`); «С прокруткой» — ширины в пикселях, появляется горизонтальная прокрутка (`'widget'`) |
| Выбор | список режимов + кнопка-иконка «копировать» | Отключено / Строка / Несколько строк, чекбоксы / Несколько строк без чекбоксов / Ячейки; кнопка (и Ctrl+C внутри грида) копирует выделение в формате для вставки в Excel |
| Экспорт | меню | «Excel (сервер)», «PDF (сервер)» — все строки под фильтром, файл строит сервер; «Excel (штатно)», «PDF (штатно)» — `exportDataGrid`, грид сам грузит все строки в браузер. Во время экспорта рядом — индикатор, текст и (для серверного) кнопка «Отмена» |
| Ещё | меню | «Задержка ответа» (сервер отвечает через 1,5 с), «Ошибка сервера» (сервер отвечает 500), «Сбросить настройки» (очищает LocalStorage приложения и перезагружает страницу) |

Ниже — чипы активных фильтров «Колонка: значение ×» (при двух и больше —
кнопка «Сбросить фильтры»), панель метрик (первая отрисовка, сортировка,
фильтрация, FPS при прокрутке текущий и минимальный, ответ сервера, отменено
запросов) и грид на всю оставшуюся высоту окна.

Колонки и подписи: ID, Дата, Завод, Линия, Продукт, Партия, Нетто, кг,
Брутто, кг, Кол-во, Код маркировки, EAN13, Статус, Оператор, Ярлыки и
закреплённая справа колонка «Действия» (Открыть, В работу, Закрыть —
уведомление с id записи, данные не меняются). Фильтр колонки — иконка воронки в
заголовке (клик по подписи сортирует, по иконке — нет): список значений с
поиском и «Выбрать всё», у чисел и дат над ним поля «с / по», кнопки
«Применить», «Очистить», «Отмена».

Размер страницы по умолчанию 50, варианты 20 / 50 / 100 / 500. Строка итогов —
«Всего строк: N» под «Продукт» и суммы «∑» под Нетто, Брутто и Кол-во; средние
«ср.» показываются только в строках групп вместе с «Строк: N» и суммами.

Высота грида подогнана под окно: заголовок (панель группировки, шапка колонок,
строка итогов) занимает 93 px, строка данных — 28 px. Строк данных видно без
прокрутки: 16 при 1200×690, 19 при 1366×768, 30 при 1920×1080.

Ключи LocalStorage (все с префиксом `dxgrid-demo:`): `state` — состояние
грида (колонки, сортировка, группировка, страница, размер страницы, выбранные
ключи до 30), `filters` — фильтры колонок, `dataset`, `width-mode`,
`selection-mode`, `demo-flags`, `scroll-widths` — ширины режима «С прокруткой»
на время работы в режиме «По ширине». Сохранение — сразу при каждом изменении
(`savingTimeout: 0`), дополнительно при уходе со страницы и `beforeunload`.

## API мок-сервера

Условия — в формате DevExtreme; запросы с условиями идут `POST
application/x-www-form-urlencoded` с теми же ключами, что читает
`DataSourceLoadOptionsParser` (`skip`, `take`, `requireTotalCount`,
`requireGroupCount`, JSON-строки `sort`, `group`, `filter`, `totalSummary`,
`groupSummary`), плюс `dataset`. POST, потому что список значений фильтра не
помещается в URL. Даты — `yyyy-MM-dd` без времени.

| Метод и путь | Что делает |
| --- | --- |
| `GET /api/health` | `{ "status": "ok" }` |
| `GET /api/datasets` | какие наборы сгенерированы: `[{ size, generated, generationMs }]` |
| `POST /api/rows/query` | ответ `DataSourceLoader`: `{ data, totalCount, groupCount, summary }`; без `take` отдаёт все строки под фильтром потоком (так работает штатный `exportDataGrid`) — тяжёлый запрос, как и `take` больше 500 или группа с `isExpanded: true` |
| `POST /api/distinct` | `dataset`, `field`, `filter`, `search?`, `take?` (по умолчанию и не больше 5 000, иначе `400`) → `{ items: [{ value, text, count }], totalCount, truncated }`; `text` — отображаемое значение (русский статус, дата `dd.MM.yyyy`, число в формате ru), поиск — по `text` без учёта регистра |
| `POST /api/stats` | `dataset`, `field`, `filter` → `{ min, max, count }` — границы для полей «с / по» |
| `PUT /api/rows/{id}/labels?dataset=n` | тело `{ "labels": ["срочно"] }`, ответ — запись; оверлей в памяти |
| `POST /api/export/xlsx`, `POST /api/export/pdf` | те же ключи + `columns` (JSON `[{ field, caption }]`); все строки под фильтром, только переданные колонки в переданном порядке, порядок строк — поля группировки, затем сортировка, значения отображаемые; XLSX пишется потоком, PDF (A4 альбомная, 45 строк на страницу) строится в памяти и отдаётся целиком |

Одновременно выполняются не более двух тяжёлых запросов (оба экспорта и
`/api/rows/query` без `take`, с `take` больше 500 — самой большой страницы
грида — или с группой `isExpanded: true`: все они отдают весь набор под
фильтром); остальные получают `429` с текстом «Сервер занят…». `/api/distinct`
и `/api/stats` делают проход по набору на каждый запрос, поэтому для них свой
предел: 8 одновременно, ещё 32 ждут в очереди, остальные получают `429` с тем
же `{ "message" }` (`AddRateLimiter`, общий на процесс, не по адресу клиента —
за NAT контейнера адрес ненадёжен). Заголовки демо: `X-Demo-Delay: <мс>` задерживает ответ (клиент ставит
1 500, сервер ограничивает 60 000), `X-Demo-Fail: 1` даёт `500` с
`{ "message": "Демонстрационный сбой сервера (X-Demo-Fail)" }`. Повреждённый JSON
в `sort`/`filter`/`group` — `400` с текстом парсера.

## Найденные ограничения

То, что DevExtreme 23.2.15 на Angular 12 не делает «из коробки» или делает
иначе, чем ждёт задание, и что пришлось обходить. Полный список по
требованиям — на странице «О программе → Итоги» (колонка «Ограничения и баги»).

### Версия и окружение

- `BrowserTransferStateModule` обязателен в `AppModule`: каждый компонент
  devextreme-angular 23.2 инжектирует `TransferState`, которого Angular 12 сам
  не даёт; сборка зелёная, в рантайме `NullInjectorError`.
- Node 24 собирает Angular CLI 12 только с `--openssl-legacy-provider`
  (webpack 5.50 использует md4).
- Тип входа `columns` у devextreme-angular — `DevExpress.ui.dxDataGridColumn` из
  бандла `dx.all`; модульный `Column` из `devextreme/ui/data_grid` TypeScript 4.3
  с ним не сравнивает (TS2321 «Excessive stack depth»), поэтому колонки
  типизированы типом бандла (импорт только типа).
- `Scrollable.container` не публичный — элемент прокрутки берётся через
  `getScrollable().element()`.
- Тип `SummaryDescriptor` требует `selector`, хотя грид шлёт `{ summaryType:
  'count' }` без него — описатели нормализуются перед отправкой.
- `exceljs` требует `@types/node` в typings — `skipLibCheck: true`.
- `DxTemplateDirective` входит в зону Angular на каждый шаблон: если грид
  перерисовывается вне зоны (вызов API грида из `runOutsideAngular` или из
  консоли), после каждой ячейки идёт полный `tick`, и страница в 500 строк с
  шаблонами рисуется 19–22 с вместо 1,2 с. Действия пользователя идут внутри
  зоны, и этого не происходит.

### Фильтры

- Штатный `headerFilter` не умеет показать диапазон «с / по» в одном popup со
  списком — список и диапазоны реализованы своими компонентами в `dx-popup`,
  открываемом иконкой в своём `headerCellTemplate`.
- У `dxPopup` в 23.2.15 нет свойства `target` — позиция через `position.of`.
- `dx-list` на 5 000 элементах рисуется 12,7–12,9 с, «выбрать всё» — 3,5 с;
  список сделан своим окном из 10 строк `dx-check-box` (8–22 мс), без
  навигации по строкам с клавиатуры.
- Колонки с уникальными значениями (`markingCode`, на больших наборах `id`)
  приходят усечёнными до 5 000 значений: подпись «Показаны первые 5000,
  уточните поиском», «Выбрать всё» становится «Выбрать показанные (N)» и
  задаёт явный список значений, а не отсутствие фильтра. Поиск идёт на сервере.
- Оператор `between` отвергается `DevExtreme.AspNet.Data 5.1.0` на `IQueryable`
  в памяти (`500`, в лог сервера уходит `Specified method is not supported`, клиенту —
  «Внутренняя ошибка сервера»), `anyof` тоже — клиент
  собирает диапазон из `>=`/`<=`, а список — из цепочки `or`.
- Штатное `calculateFilterExpression` колонки даты ждёт `Date` или `yyyy/MM/dd`
  и превращает строки `yyyy-MM-dd` с сервера в `Invalid Date` — у колонки своё
  выражение, условие уходит как есть.
- `useMaskBehavior: true` у `dx-date-box` со строковой сериализацией бросает
  `value.getTime is not a function` на blur — маска выключена, ввод
  `dd.MM.yyyy` свободный.
- Поля «с» и «по» нельзя ограничивать друг другом через `min`/`max`
  редактора: набранная дата раньше «с» делает `dx-date-box` невалидным без
  события, а `dx-number-box` молча зажимает число — и модель диапазона не
  получает шанса подтянуть парное поле. Оба редактора ограничены границами
  набора, «с» ≤ «по» держит модель.
- Тип `value` у `dx-number-box` не допускает `null`, хотя `reset()` его даёт —
  нужен типизированный помощник.
- `filterPanel` выключен: его filterBuilder меняет `filterValue` мимо состояния
  страницы и умеет операторы, которые сервер отвергает; вместо него чипы над
  гридом.
- Фильтр по ярлыкам идёт по служебному полю `labelsKey` (`|а|б|`, оператор
  `contains`); грид принимает в `filterValue` только поля своих колонок
  (ошибка E1047), поэтому поле заведено скрытой колонкой — и она попадает в
  сохранённое состояние.

### Колонки и состояние

- Ширины режима «По ширине» — проценты из `fitPercent` определения колонки;
  DevExtreme хранит и ручное растягивание в процентах, поэтому сохранённое
  состояние оставляется как есть и дополняются только отсутствующие ширины.
  Следствие: изменение `fitPercent` в коде не доходит до уже сохранённого
  состояния до «Сбросить настройки». Без ширин грид делил бы страницу поровну
  и обрезал заголовки, поэтому доли заданы по содержимому; минимальная ширина
  колонки 40 px.
- Ширины режима «По ширине» при переходе в «С прокруткой» и обратно не
  сохраняются (ширины режима прокрутки — сохраняются в `scroll-widths`).
- Подписи строки итогов в «По ширине» не переносятся: при ширине грида меньше
  ≈1 400 px «Всего строк: 1 000» выходит за свою ячейку, при ≈800 px подписи
  итогов наезжают друг на друга (измерено: 834 px — ещё раздельно, 784 px —
  наезд) — на гриде уже ≈850 px использовать «С прокруткой».
- Переключение режима ширины стоит один запрос страницы: `state(...)`
  заканчивается сбросом `dataController`.
- Закреплённая колонка — вторая таблица на все строки: на странице в 500 строк
  ≈0,4 с отрисовки и 1–3 FPS (измерено на закреплённой колонке действий).
- Фильтры живут в состоянии страницы, а не грида: `customSave` вырезает
  `filterValue`, `customLoad` подставляет его обратно — иначе `applyState`
  сбросил бы привязанный `filterValue`. Службы фильтров и демо-флагов
  перечитывают хранилище при каждом открытии страницы: иначе ключ, удалённый
  на странице «Сохранённые настройки», возвращался из памяти — чипом или
  заголовком `X-Demo-Delay`.
- Два открытых таба одной страницы перезаписывают друг другу
  `dxgrid-demo:state` (`savingTimeout: 0` и `beforeunload`): порядок и
  видимость колонок берутся из того таба, который сохранился последним.
- Смена набора сбрасывает страницу и у `DataSource`, и в `paging.pageIndex`
  грида: иначе следующая смена размера страницы возвращала старый номер и
  запрашивала строки за пределом набора.
- Статус сортируется по коду enum, а не по подписи: `customizeText` оставляет
  `selector: 'status'` в запросе, `calculateDisplayValue` увёл бы сортировку на
  клиент.

### Выбор и копирование

- Режима выделения ячеек в DataGrid 23.2 нет — свой код на `onCellClick` /
  `onCellPrepared` (Ctrl — переключение, Shift — прямоугольник); выделение
  сбрасывается при смене страницы, сортировки, фильтра, группировки и набора;
  ячейка «Ярлыки» не выделяется (клики уходят в редактор).
- «Выбрать всё» — только на странице (`selectAllMode: 'page'`): `'allPages'` на
  1 000 000 строк грузит весь набор без `take` — 343 МБ, 4,4 с, куча 852 МБ,
  копирование миллиона строк — 31,7 с без отклика вкладки; `deferred: true` не
  помогает.
- Выбор больше 30 строк после перезагрузки не восстанавливается: ключи не с
  текущей страницы грид догружает фильтром `or`, а если
  `encodeURI(JSON.stringify(filter))` длиннее 1 500 символов
  (`selection.maxFilterLengthInRequest`, в `.d.ts` 23.2.15 не вынесен), грузит
  весь набор без фильтра. Предел в 30 ключей (1 196 символов) не учитывает
  фильтр колонок, который грид дописывает к этому запросу: при нескольких
  активных фильтрах не восстанавливается и меньшее число строк.
- Копирования в буфер у DataGrid нет — своя сборка TSV (заголовки видимых
  колонок, отображаемые значения, экранирование по правилам Excel, CRLF). На
  HTTP без `navigator.clipboard` — запасной путь через `textarea` и
  `execCommand('copy')`; `textarea` превращает CRLF в LF, поэтому текст ставится
  в `clipboardData` слушателем `copy`.
- Если данных части выбранных строк у грида нет, копирование отказывается
  целиком с предупреждением.

### Загрузка, ошибки, отмена

- Отмены HTTP у DataGrid нет: `DataSource.cancel` лишь отвергает свой deferred,
  запрос продолжает идти. Отмена сделана отпиской от `HttpClient` (браузер
  прерывает XHR); promise отменённой загрузки надо завершить явно пустым
  ответом, иначе панель загрузки грида остаётся.
- Пробы `take: 1` счётчика групп DataGrid шлёт параллельно: в одной группе
  отмены вторая обрывала первую и грид молча оставлял прежние строки — пробы и
  загрузка всех строк идут вне группы отмены.
- `DataSource.pageIndex(0)` после смены набора — операция «только страница»:
  `totalCount` грид берёт из кэша и пейджер оставался на 20 страницах для
  миллиона строк; нужен `refresh()`.
- `DataSourceLoader` (DevExtreme.AspNet.Data 5.1.0) считает `totalSummary` по
  отсортированному запросу: на 1 000 000 строк страница с сортировкой и
  итогами стоила 480–540 мс на сервере против 28–45 без итогов (полная
  сортировка под итоги, тогда как странице хватает частичной). Сервер считает
  итоги вторым проходом по отфильтрованному набору без сортировки
  (`RowsQuery`): 260–295 мс в Release.
- Ошибку грид показывает своей строкой (`errorRowEnabled`); здесь она выключена
  и ошибка показывается своей полоской с текстом сервера и «Повторить», прежние
  строки остаются.
- Метрик грид не даёт: своя служба на `performance.now()` и
  `requestAnimationFrame`, точки — события грида. FPS считается, пока идут
  события `scroll`, для этого `scrolling.useNative: true` — имитированная
  прокрутка DevExtreme (по умолчанию на Windows) событий `scroll` не даёт.

### Шаблоны и группировка

- Шаблон — компонент Angular на ячейку: 1 000 экземпляров на странице в 500
  строк — ≈0,3 с отрисовки и 2–4 FPS при прокрутке.
- Колонка ярлыков (массив) не сортируется и не группируется; после сохранения
  строка обновляется через `store.push` без запроса, `labelsKey` в кэшированной
  строке устаревает (клиент его не читает). Высота строки 28 px: чипы ярлыков
  в одну строку, не поместившиеся обрезаются.
- При раскрытой группе на второй странице грид шлёт две параллельные пробы
  `take: 1` (`loadGroupTotalCount`).

### Экспорт

- Штатный `exportDataGrid` при удалённых данных грузит весь набор в браузер
  одним запросом без `take`. Предел на машине разработчика: Excel — 100 000
  строк (8,2 с, ответ 34 МБ, куча 500 МБ, процесс 1,15 ГБ); PDF — 100 000 строк
  не завершились за 10 минут, вкладка заморожена; на 1 000 000 строк оба
  штатных экспорта убивают процесс вкладки на 4,8–5,1 ГБ, файла нет. Штатный
  экспорт отменить нельзя. Поэтому экспорт всех данных — серверный.
- `exportDataGrid` на отклонённой загрузке (например, `429` ограничителя) не
  завершается никогда: панель «Экспорт…» остаётся, `loadPanel` грида остаётся
  выключенным. Страница отдаёт ему отказ пустым ответом; экспорт завершается,
  пустой файл не сохраняется, пользователь видит текст ошибки.
- Сгруппированные колонки в файле идут первыми (по ним сервер упорядочивает
  строки) — порядок колонок отличается от экрана при группировке.
- Серверный PDF строится в памяти целиком (PDFsharp): +1,2 ГБ на 1 000 000
  строк, первый байт — после сборки документа (33–41 с). PDF от 100 000 строк
  запрашивает подтверждение с оценкой числа страниц.
- Серверный PDF подбирает ширины колонок по первой странице, и на A4 альбомной
  при шрифте 7,5 pt все 14 колонок целиком не помещаются: длинное значение
  (код маркировки) обрезается с «…». Полные значения — в XLSX.
- Штатный Excel пишет сырые значения с форматами ячеек, серверный —
  отображаемый текст.
- Экспорт выгружает подписи колонок как на экране — после сокращения подписей
  это ID, Кол-во, EAN13.
- Под `ng serve` «Отмена» серверного экспорта обрывает запрос только в
  браузере: dev-прокси (`http-proxy`) не закрывает соединение с сервером, и
  сервер достраивает PDF до конца, удерживая слот ограничителя (слот занят
  ещё через 19 с после отмены, свободен через 41 с). При запросе напрямую к
  серверу обрыв доходит и слот освобождается в пределах 7 с; в сборке, где
  сервер отдаёт клиент сам, прокси нет.

## Без `any`

`: any`, `as any`, `<any>` в исполняемом коде `src/` и `server/` нет. Что похоже,
но не оно:

- `src/polyfills.ts` — четыре `(window as any)` в закомментированном шаблоне
  Angular CLI для флагов zone.js; код не выполняется и не компилируется.
- `src/app/features/about/about.component.spec.ts` — `jasmine.any(Number)`,
  это матчер Jasmine, не тип.
- Тесты компонента грида подменяют `DxDataGridComponent` объектом с нужными
  методами через `as unknown as DxDataGridComponent` — узкое приведение, не
  `any`.
- Сервер: `object` в `DistinctItem.Value` / `StatsResponse.Min`, `Max` (значение
  колонки любого типа в JSON) и `IDictionary<string, object>` строки для
  MiniExcel (сигнатура библиотеки); `dynamic` не используется.

## Публикация

Демо: **<http://82.38.66.177:8095/>**. Исходный код:
<https://github.com/olegvphoenix/devextreme-grid-demo>.

Один контейнер Docker с многостадийной сборкой (Node для клиента, SDK 8,
рантайм `aspnet:8.0`), сервер отдаёт собранный клиент из `wwwroot`, порт `8095`
наружу, лимит памяти 4 ГБ и Workstation GC (`DOTNET_gcServer=0`: PDF на
1 000 000 строк при Server GC занимает до 6 ГБ), `--restart unless-stopped`.
Выкладка текущего коммита: `bash scripts/deploy-pl-test.sh`.

Адрес работает по HTTP, поэтому `navigator.clipboard` недоступен и копирование
идёт запасным путём через `document.execCommand('copy')`. Первый запрос к
набору на 1 000 000 строк после запуска контейнера занимает несколько секунд:
набор строится при первом обращении.

Демо открыто в интернет **без авторизации**: данные синтетические, записи не
меняются (кроме ярлыков в памяти процесса). Нагрузку ограничивают серверный
лимит тяжёлых запросов (не более двух одновременно: экспорт, запрос без
`take`, `take` больше 500, раскрытая группа) и предел одновременных запросов
списков значений и границ (8 + очередь 32); `take` у `/api/distinct` — не
больше 5 000.
